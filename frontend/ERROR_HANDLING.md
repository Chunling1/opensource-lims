# 错误页面与恢复操作

应用继续使用 Vue Hash 路由。页面显示的错误编号是前端呈现；不会更改 HTML 请求的 HTTP 状态码。未来接口层只需抛出 AppError，无须由后端返回页面 HTML。服务器未能送达 HTML 的错误需要部署侧处理。

## 展示层级

| 位置 | 展示 | 恢复 |
| --- | --- | --- |
| IndexedDB／身份初始化失败、应用框架渲染异常 | 独立整页 | 重试初始化或重建框架，不清空数据 |
| 首次页面读取失败、403、缺失记录／未知地址 | 保留导航的内容区错误页 | 合适的读取重试、返回所属列表或切换身份 |
| 已加载页面刷新失败 | 原内容上方局部提示 | 保留上次内容，手动读取重试 |
| 保存、审批、签发、下载、附件失败 | 原表单、弹窗或附件区提示 | 用户修正后重新操作，不自动重放写入 |
| 字段校验 | 表单摘要和字段下方反馈 | 使用 is-invalid、aria-invalid、aria-describedby |
| 并发版本冲突 | 保留输入，显示查看最新记录入口 | 新标签页查看；确认后才能重新加载并覆盖输入 |
| 懒加载页面失败 | 保留当前工作空间 | 重试导航；模块加载失败被浏览器缓存时，手动刷新页面 |
| 主脚本未能运行 | index.html 中最小静态提示 | 资源加载错误立即显示，启动 15 秒未挂载也显示；手动刷新 |

400／401／403／404／500／503 预览入口为 `/#/errors/编号`，独立页为 `/#/errors/编号/standalone`。组件验证页提供链接，业务菜单不增加错误页面。`/forbidden` 和未知路由复用相同组件。真实初始化错误由根状态控制，不依赖预览路由。

当前 401 对应失效演示身份，不是生产登录。工作空间锁定仍使用原锁定弹窗。断网状态不会阻断 IndexedDB 业务，也不会自动进入离线页。502／503／504 接口异常可用 UNAVAILABLE 加对应 status 表达；只有明确的 MAINTENANCE 使用维护插画和语义。

## 开发接口

`src/services/common/errors.ts` 定义 AppError、ErrorCode、normalizeError、字段错误和有限诊断缓冲。常用构造：

```ts
throw new AppError('VERSION_CONFLICT', '记录已更新，请核对最新版本。')
throw problem('VALIDATION', '请填写名称。', 'name')
throw new AppError('RATE_LIMITED', '请稍后重试。', { retryAt: Date.now() + 3000 })
```

稳定错误码来自服务抛出点，不匹配中文消息来猜测类型。未知 Error 只显示统一文案；原始 cause 不渲染。诊断缓冲只保留最近 50 条编号、错误码和时间，不存储业务输入或完整响应，不写 IndexedDB；同一异常对象去重。

- `ErrorPage`：独立／内容区容器与模板插画。
- `ErrorNotice`：局部持久提示；读取可显式启用 retry；写操作不挂自动重试。
- `LoadState`：hasData 决定读取失败是替换内容还是保留已有结果。
- `ErrorBoundary`：内容区与应用框架的渲染边界；导航到另一页面解除内容区边界。
- `useUnsavedChanges`：页面刷新／关闭前提示；既有路由离开确认仍保留。

业务页把 loadError、操作 error、弹窗 actionError 和附件 attachmentError 分开。不要把保存异常传给页面初始化重试。身份变更会清除上一身份的业务数据；详情与列表切换使用请求序号防止旧响应覆盖新页面。列表位置在当前会话内记忆，详情错误返回时恢复筛选和分页。

HTTP 层将来需按实际提交结果区别“明确未写入”与“写入结果不确定”。只有本地事务回滚确认的写入错误提示“数据未保存”；未知异常不作保存成功／失败的确定性承诺。

## 模板来源与约束

404 使用 `auth-404-cover.html` 与 `error400-cover.png`（图片内容实际是 404）。500 使用 `auth-500.html` 与 `error500.png`。维护使用 `pages-maintenance.html` 的本地 maintenance.png 和 auth-page-wrapper 结构。其他状态使用模板图标、卡片和工具类。仅独立页使用 min-vh-100。图片通过 BASE_URL 加载，不引入外站动画；未修改 docs 原模板或新增业务 CSS。

## 验证

- `npm test`：错误分类、诊断脱敏／容量、返回地址、服务状态与现有业务测试。
- `npm run test:e2e`：错误路由、丢失记录、写入失败保留表单、冲突确认、刷新与首次读取失败、初始化恢复、脚本失败、离线本地操作、字段反馈、渲染边界及主题布局。
- `npm run build`、`npm run check:styles`、`npm run test:production`：类型、独立产物、模板资源和子目录部署。
- 可设置 `PLAYWRIGHT_BASE_URL=http://127.0.0.1:4186` 使用独立测试端口。故障由测试拦截浏览器存储或服务注入，不提供生产故障开关。
