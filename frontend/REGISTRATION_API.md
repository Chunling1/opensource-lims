# 委托登记 HTTP 模拟接口

本文记录委托登记及后续接入的业务 HTTP 模拟接口，包括上岗证信息。不新增 CSS，不改变业务数据库存储结构。

## 运行及边界

`npm run dev` 或 `npm run preview` 通过 Vite 插件挂载 Node 中间件。默认同源前缀 `/api/registration`；`VITE_REGISTRATION_API_BASE` 可覆盖前缀，但目标仍需提供相同协议。静态文件本身不包含服务端，部署时需要独立后端或代理。

模拟记录仅保存在 Node 进程内存，每个浏览器 Cookie 会话独立，刷新保留，重启服务重置。会话最多 100 个；创建会话时淘汰超过 8 小时未访问的会话，容量满时淘汰最早加入的会话。Cookie 为 HttpOnly、SameSite=Strict。`X-Demo-Actor` 仅从固定演示身份中选择角色，不能作为生产身份验证。接入真实服务时必须替换认证及持久化实现。

## 关联与查询

- 一张委托对应多个样品，每个新登记样品必须指定所属委托；只有未完成的委托可新建关联；委托信息在新建样品时复制为独立资料，之后由样品单独保存。旧委托配置检测项目时仍限制在其范围内；新委托没有检测项目字段，样品表单从有效项目目录选择。
- 委托复选框同时用于批量导出及样品关联范围，全选仅选当前页；点击行快捷勾选该条委托（替换原勾选）。
- 样品默认“当前委托”页签，传已勾选的 `commissionIds`，服务端合并过滤、计数和分页；未勾选时不请求样品并清空列表。`scope=all` 为“全部样品”页签，不传委托限制，但保留勾选供切回时使用。勾选变化切回当前委托。
- `current` 路由参数保存逗号分隔的勾选 ID，兼容原单 ID 地址；不缓存全量资料。多选样品表增加所属委托列；委托行菜单的新增样品只关联该行，保留原勾选和返回上下文。当前委托页签只在单选一张未完成委托时提供新增样品快捷入口；全部样品页签新增时仍须选择单张未完成委托。
- 委托查询、排序、翻页清空委托勾选及当前范围；勾选变化或切换样品页签使样品回到第一页并清空样品勾选。刷新、操作后重新加载及表单返回保留委托勾选。
- 两张表分别维护加载、错误、重试、取消及请求序号；旧请求不会覆盖新查询。
- 操作列参考 Tabler `tables-basic.html` 的 Bordered Tables 示例，每行仅显示竖向三点菜单。查看、修改、新增样品、完成/取消完成按权限和状态呈现，所有操作仅针对当前行；菜单浮层挂载到页面，避免表格横向滚动容器裁切。新增委托和导出保留在卡片工具栏。
- 前端不加载全量委托/样品，不在页面过滤数据。只有当前页、当前委托摘要及按需打开的单条详情。委托选择弹窗每页 5 条，提交关键词后远程搜索。
- 查询、排序、分页、当前委托与折叠状态保存在路由；表单返回地址经过站内路径校验。
- 分页外观复用 Tabler `apps-crm-companies.html` 的 `pagination-wrap/listjs-pagination` 结构及原版样式，使用数字页码和当前页主题色；页数较多时显示省略号，按钮数量保持有限。仅复用样式，不引入 List.js 的前端全量分页。
- 登记页内的查询参数更新不重置页面滚动位置；样品刷新时保留旧表格的占位，隐藏旧内容并禁用操作，避免加载期间高度骤降。进入详情等其他页面仍从顶部显示。

## 接口

### 上岗证信息

`/quality/personnel/certificates` 页面通过下列模拟接口访问数据，沿用同一 Cookie 会话。人员与人员登记共享记录；初始会话包含 12 名人员、72 张上岗证及其核准项目。刷新保留新增、编辑、删除与附件，服务重启或会话失效后重置。界面不再持有独立示例数组。

接口前缀为 `/api/registration/quality/certificates`：

- `GET /options`：当前权限范围内的部门、已有类别选项。
- `POST /{people|certificates|projects}/query`：`filters`、`scope`、`parentIds`、`page`、`pageSize`（5/10/20）。服务端筛选、计数、分页。
- `POST /{people|certificates|projects}/export`：同一查询范围，另传 `columns` 和可选 `ids`，返回 CSV。
- `GET /{certificates|projects}/:id`：单条详情；附件仅返回引用。
- `POST /{certificates|projects}`、`POST /{certificates|projects}/:id/save`：新增或带 `version` 编辑。项目新增传 `certificateIds`，所有归属校验通过后一次性保存。
- `POST /{certificates|projects}/:id/delete`：版本校验后删除；删除证书还须传确认时的 `projectCount`，关联项目和附件同时删除。
- `GET /certificates/:id/files/:fileId`：校验权限及所属证书后下载附件。

这些请求沿用默认 2000 ms 延时及 `LIMS_MOCK_QUERY_DELAY_MS` 配置。附件复用 `/attachment-drafts/:draftId/*`，`scope=certificate`：上传显示实际传输进度，表单保存提交文件引用；关闭附件面板可继续上传，放弃表单会取消上传并清理草稿。修改关联项目也会更新证书版本，避免使用旧确认删除已变化的证书。

### 委托列表列配置

委托列表默认显示委托编号、样品工程名称（表单项目名称）、委托单位、委托状态、委托日期、应收费用、委托经办人。合同编号可选显示在委托编号后；委托人、建设单位、施工单位可选显示在经办人后。显示列菜单可调整除委托编号之外的业务列，勾选和操作列始终保留，支持恢复默认。名称和单位自然换行，其余列保持紧凑，超宽内容仅在表格内部滚动。

`cColumns` 是按白名单校验的逗号分隔列标识；未提供时使用默认列，并兼容旧 `contractColumn=1`。显式配置优先于旧参数；切换后移除旧参数，恢复默认清除两者。列顺序固定，不接受路由自定义顺序。列配置仅影响显示，不触发列表重新查询，不清空勾选、分页或样品范围；刷新与详情/表单返回均通过路由还原。

摘要新增 `commissionDate/contact/receivableAmount/constructionUnit/constructionCompany`。委托日期仅取表单日期，旧记录缺失时显示“—”，不使用 `createdAt` 替代。委托列表及导出支持 `sort=commissionDate`，空日期在升降序中均排最后；委托 `from/to` 筛选委托日期（含首尾当天），缺失委托日期的记录在有日期条件时不匹配；样品仍筛选登记日期且不接受委托日期排序。应收费用、建设单位、施工单位暂由模拟服务返回 `null`，不从合同或其他金额推断，不增加录入字段或存储结构。金额缺失显示“—”，零值显示 `0.00`。委托 CSV 始终包含全部 11 个业务字段，沿用权限、筛选、全匹配页/选定 ID 范围和 CSV 转义规则，不受显示列影响。

所有响应禁用缓存。先调用 `POST /session` 取得演示会话 Cookie，其余请求带 `X-Demo-Actor`。有请求体时使用 JSON。

| 方法 / 路径 | 内容 |
| --- | --- |
| POST `/commissions/query` | 委托筛选及分页 |
| POST `/samples/query` | 样品筛选及分页 |
| POST `/contracts/query` | 合同弹窗：提交 `code/keyword/searchField/from/to/ownDepartment/page/pageSize`，服务端按角色及部门分页查询 |
| POST `/organizations/query` | 单位弹窗：提交 `keyword/page/pageSize`，服务端按名称及权限范围筛选后返回当前页 `id/name` 和总数 |
| GET `/commissions/:id/summary` | 当前委托摘要 |
| GET `/{commissions或samples}/:id` | 单条完整详情 |
| POST `/{commissions或samples}` | `{ input }` 新增 |
| PUT `/{commissions或samples}/:id` | `{ input, version }` 修改 |
| POST `/{commissions或samples}/:id/actions` | `{ actionId, version, reason?, changes? }` 状态操作 |
| POST `/commissions/:id/attachments` | `{ version, file }` 附件保存 |
| GET `/commissions/defaults` | 新增委托默认值，返回 `{ commissionDate: "YYYY-MM-DD" }`；日期取服务器当前日期，禁止缓存 |
| DELETE `/commissions/:id/attachments/:attachmentId` | `{ version }` 删除指定附件，返回更新后的委托 |
| POST `/{commissions或samples}/export` | 查询条件或选定 `ids`，返回 CSV |

查询体示例：

```json
{
  "commissionIds": ["demo-wt-1", "demo-wt-2"],
  "keyword": "地表水",
  "status": "pending",
  "page": 1,
  "pageSize": 10,
  "sort": "createdAt",
  "direction": "desc"
}
```

查询字段可选：`commissionCode/keyword/status/from/to/customer/owner/contract/category/commissionId/commissionIds/ids/eligibleOnly/page/pageSize/sort/direction`。`eligibleOnly` 用于可关联委托选择。关键词匹配委托编号、名称、单位，或样品编号、名称；单位、合同、登记人支持文本包含匹配。日期为 `YYYY-MM-DD`，默认不限制。

分页从 1 开始；委托允许 5/10/20，样品允许 10/20/50 条。排序只允许 `code/createdAt` 和 `asc/desc`。响应为 `{ items, total, page, pageSize }`；列表项仅带表格字段及版本、样品所属委托摘要，不携带附件或审计记录。超出末页时返回实际末页。服务端先校验角色/部门，再筛选、稳定排序和分页；不可访问的关联编号、名称不返回。

查询结果导出忽略分页并导出所有匹配记录；选定导出传 `ids`，样品同时传已勾选的 `commissionIds`。`commissionIds` 最多 50 个 ID，每个 ID 都校验委托访问权限；传空数组返回空结果，省略才表示不限制委托。原单委托 `commissionId` 保持兼容；两者同时提交时取交集。CSV 沿用 BOM、字段转义及公式前缀保护。

错误响应为 `{ error: { code, message, fieldErrors?, diagnosticId } }`，HTTP 状态包含 400、401、403、404、409、422、500。修改与状态操作使用 `version` 检查冲突。创建、关联、审计在模拟服务内一次写入；失败不提交临时状态。

## 接入真实后端

委托登记列表从查看、编辑、打印等子页面返回时，统一向后端重新查询委托列表、当前范围的样品列表及选中委托摘要，不判断是否修改、不维护业务缓存失效规则。查询条件、分页和显示列由返回地址保留；当前身份的内存中仅保存上一屏表格、勾选和滚动位置，用于查询完成前的展示过渡。加载期间保留原表格，最新结果替换旧行，并保留仍存在且可选的样品勾选。附件弹窗的上传、删除仅更新附件和版本，不刷新背景列表。展示快照不含附件正文或表单草稿，切换身份、离开委托登记流程或刷新浏览器后不复用。

### 委托表单与首次保存

登记模块的委托状态统一为“未完成 / 已完成”，首次保存为未完成。`complete` 将单条未完成委托标记为已完成，`uncomplete` 恢复为未完成，不再检查报告或检测任务，也不提供提交评审、开始执行、归档、更改及作废审批操作。已完成委托禁止修改、新增关联样品及上传附件；查看与下载已有附件仍可使用。取消完成后恢复上述操作。前后端都执行状态及角色/部门检查，状态接口仍校验版本并写入审计；不修改其他业务页面的状态流程。

新增、修改、查看共用同一套委托表单分区，查看页以只读输入框展示。打印已实现独立的前端页面与 HTTP 模拟服务，详见[界面流程设计](docs/commission-print-design.md)：产品可选择第一至第四联，工程可选择第一至第三联；后台根据已保存内容和后台模板异步排队生成 PDF，前端只提交选项、查询任务和预览结果。用户可离开后从“打印 → 生成记录”找回。委托列表和样品列表的单条菜单均提供打印入口；空委托的打印菜单禁用。模拟服务返回演示 PDF，正式模板及持久化队列待接入。

表单及详情仅保留截图中的委托基本信息、委托单位信息、工程基本属性、业务办理信息和财务相关信息五个分区。附件统一通过委托登记列表行菜单管理，新增、查看和编辑委托页面均不显示附件区。移除检测项目、样品来源、结算条件、要求完成日期、折扣、税率、客户要求和备注等额外表单内容；模拟接口中的旧字段保留兼容已有记录。当前不设置业务必填项，仍校验已填写的日期、字段长度、数值格式及可访问资料。`name` 对应表单的项目名称，在委托列表中继续作为委托名称展示。

“保存”首次调用 POST，由服务端生成 `id/code`，随后替换为该记录的编辑地址并保留 `returnTo`。后续保存调用 PUT，编号保持不变。“保存并返回”保留原返回查询上下文的行为。编号、经办人、状态和审计信息不能由客户端覆盖。

合同弹窗显示合同号、合同名称、委托方、工程名称、工程地址、施工单位、登记状态。默认勾选本部门合同，日期默认不限；合同编号已合并到“查询内容”选项，与合同名称、委托方、工程名称等共用关键词输入框，默认全部；点击查询后提交 HTTP。查询控件采用模板默认尺寸，宽屏按内容宽度横向排列，小屏自然换行。接口仍兼容旧的独立 `code` 条件。取消本部门限制仍不得超出身份权限范围。弹窗顶部查询区、底部分页和确认按钮固定在各自区域，中间列表独立滚动，不滚动整个弹窗；布局使用模板弹窗和 flex/overflow 工具类。弹窗支持每页 5/10/20 条、首页/尾页及跳页；翻页或重新查询清空待选合同，单选后点击确定才回填，返回不改变表单。合同弹窗按需加载匹配页，传 `contractId` 保存。服务端重新校验合同访问范围，并从合同资料确定合同号、外部ERP项目编号、外部ERP项目类型，不信任客户端提交的带入字段。其他箭头字段的选择和联动规则尚待确认，当前保留录入；发票类型使用模板下拉框，提供增值税普通发票、增值税专用发票两种选择，新增默认普通发票；保持非必填，服务端校验已选择的类型。

扩展字段定义在 `src/types/commissions/commissionForm.ts`，包含单位、工程、经办和开票资料，旧模拟记录兼容缺省值。经办部门不能超出演示身份范围；不修改记录原有的数据归属部门。

合同甲方、其他甲方（付款方）、委托单位共用单位选择弹窗。前两项单选，委托单位多选并支持直接输入、选择后编辑；多个名称使用中文分号连接，沿用委托的 `customer` 文本快照，不新增存储结构。三个字段可清除，保持非必填。单位名称查询需提交 HTTP，默认每页 10 条，可选 5/10/20 条，支持跳页；只保留当前页和用户勾选的名称，不预加载全量单位。查询区、分页和确认按钮固定，仅中间列表滚动。单选翻页和重新查询清空待选项；多选跨页及查询保留勾选，全选仅作用于当前页，重新打开时从输入框按中文分号还原已有名称。确定后仅回填目标字段，返回不改变表单；关闭或切换身份取消在途请求。地址、法人、电话和邮编仍由用户录入，暂不增加未确认的联动。手工输入不新增单位档案。新建样品复制所属委托的单位等信息；样品中的单位信息可独立修改，不要求始终与原委托一致。

委托附件通过委托登记列表每行的“附件管理”菜单打开对话框，上传、下载、删除均在对话框内完成；新增、查看、编辑委托页面均不显示附件区，新建委托首次保存后可从列表管理附件。未完成委托且具有写权限时可上传、删除，每个附件不超过 20 MB；已完成委托只允许查看和下载。上传和删除仍校验角色、部门范围、状态及版本，更新版本和审计记录。删除需确认；请求期间防止重复操作，版本冲突或网络结果不确定时先刷新核对；附件操作不改变列表查询、分页和勾选。

### 样品登记表单

样品以 `commissionInfo` 保存委托信息的独立副本，包含基本资料、单位、工程、业务办理和财务信息。仅在新建时选择委托并复制；编辑及查看样品直接读取自身资料，不重新加载原委托单填充表单，也不回写原委托。修改原委托不会更新已有样品。委托编号、委托日期和经办人由服务端保留来源值，其余截图中的可编辑字段与样品信息一起提交和保存。样品列表、导出中的单位与联系人取样品副本；版本检查和样品只读状态仍生效。模拟种子数据在生成时直接包含副本，无历史数据迁移。

`GET /samples/defaults` 返回报告交付等模拟选项，不提供可编辑日期的默认值。新增样品的送样日期、生产日期、要求试验日期、抽样时间、内外部报告承诺时间、约定检测日期使用客户端本地当天日期；编辑时保留原值，勾选启用的日期项为空时才补入客户端当天。委托日期仍由服务器提供且不可编辑。检测方案、检测依据通过独立查询接口按需获取。新建、修改样品的 `input.details` 保存公共信息、内部备注、抽样信息、费用和委托方要求，字段定义见 `src/types/commissions/sampleForm.ts`。日期、数量、费用和选项类型在服务端校验；编号、状态、版本仍由服务器控制。

公共信息中的 `urgent` 对应“是否加急”，新建默认 `false`；`taskRecipient` 对应“任务单领取人”，选项由 `/samples/defaults` 返回，两项随样品保存并回显。

评定标准使用与检测依据相同的多选列表及受保护文本框，模拟阶段复用当前检测方案的标准目录及查询、解析接口。通过 `assessmentStandardIds/assessmentStandardSeparators/assessmentEnglishBookMarks/assessmentStandard` 独立保存选择、逐项分隔符、书名号格式及生成文本；服务端按 ID 重新生成内容。未启用“是否使用评定标准”时禁用并清空该栏，切换检测方案也清空已有评定标准；列表外内容不能直接输入。

未勾选的评定标准及约定日期不会保留有效值。保存、保存并返回沿用原样品登记事务与版本检查；页面用 Toast 提示保存结果。报告编号 `reportCode` 由服务端首次保存时生成并在后续编辑中保持不变，客户端不能指定或修改；未保存时显示“保存后自动生成”。当前模拟服务使用 BG 前缀编号，正式编号规则由后台提供。计价结果保持空白只读，不据其他字段推算。

子项目信息支持本地草稿的增删改查和分页，随样品提交 `details.subprojects` 一起保存。列为子项目名称、核算部门、业务三级分类、子项金额、收款金额、收款类型、付款说明和备注，序号由展示位置生成。金额独立录入，不与标准价格、已缴费或只读计价结果联动。每张样品最多 200 个子项目，金额最多两位小数。完成登记、批量处理、导入、计价及通用样品附件流程仍待业务确认。选项字典为模拟数据，接入正式服务时以后台配置为准。

### 生产接入

检测方案使用 `POST /test-plans/query`（前缀 `/api/registration`）：无条件时返回分组，传 `parentId` 按需返回该分组方案；`keyword` 按名称或代码查询方案，`page/pageSize` 在服务端分页。返回节点包含 `id/name/kind/code/groupName`，目录不能选择。样品通过 `details.testPlanId/testPlan/testPlanCode` 保存所选方案，服务端重新校验部门访问范围并回填正式名称与报告代码；表单显示“方案名称（报告代码）”，代码不允许手动编辑。新增样品必须选择检测方案，前后端均校验 `testPlanId`。样品表单将方案选择与普通字段纳入同一次校验，统一使用字段下方的错误提示；保存时按可见字段从上到下、从左到右定位首项，隐藏页签中的错误在切换页签后定位。首次保存后方案不可更换或清空（包括合同评审中的编辑），后端保留已存名称与代码并拒绝变更 ID。历史无方案记录仍可编辑其他字段，不自动补填方案。新建期间取消弹窗不修改表单，确认同一方案保留依据，切换或清除方案时清空依据；检验项目不联动更改。

检测依据使用 `POST /test-bases/query`，必须提交 `planId`；支持标准编号 `code`、名称 `name`、类别 `category`、资质 `qualification`、受控号 `controlNumber`、部门类别 `departmentCategory`、本部门标准 `ownDepartment`，以及 `sort`（code/name/implementedDate + :asc/:desc）、`page/pageSize`（10/20/50）。先校验方案权限和部门范围，再筛选、排序、分页；返回完整表格摘要和可用部门类别。`ids` 精确查询已选记录，空数组返回零条。浏览器仅保存当前页和已选 ID，不预加载所有标准。

`POST /test-bases/resolve` 接收 `planId/ids/englishBookMarks` 及可选的 `separators`，重新校验每项标准的方案关联、权限及分隔符，返回 `ids/text/englishBookMarks/separators`。最多选择 50 项，支持跨页、跨查询保留选择，全选只作用于当前页。取消不回填；清空后确认可删除已有依据。英文书名号仅影响回填格式（暂按半角 `< >`），默认中文 `《》`。保存样品使用 `details.testBasisIds/testBasis/englishBookMarks/testBasisSeparators`，服务端依照 ID 重新生成文本，不信任客户端拼接内容。标准数据为模拟目录，不代表真实标准或资质。

`src/services/commissions/registrationApi.ts` 仅负责 HTTP；`server/registrationApi.ts` 定义协议及摘要，`server/registrationDomain.ts` 为模拟业务逻辑。真实大数据服务应在数据库执行关联筛选、计数和分页，并按委托 ID、部门及排序字段建立合适索引；内存模拟实现不代表生产数据库性能。真实创建关联需要数据库事务，生产认证应从可信服务端会话解析身份，不接受演示身份请求头。

验证覆盖实际 HTTP 分页/筛选、权限、导出、会话隔离，以及浏览器查询提交、委托联动、返回恢复、旧响应隔离、失败重试与布局。


## 委托打印模拟接口

- GET /:kind/:id/print-context：返回 kind、id、code、name、canPrint。kind 为 commissions 或 samples；无样品的委托不可打印。
- POST /:kind/:id/prints：提交 documentType（commission/sample）、documentCode（单号）、type（product/engineering）、layout（normal/extended）、copies，返回 202 和任务。服务端校验对象类型和单号与地址对应记录一致。前端不提交样品清单或范围版本。
- GET /:kind/:id/prints?page=1&pageSize=5：服务端分页生成记录（每页 5/10/20）。
- GET /:kind/:id/prints/:task：查询 queued/running/ready/failed 状态。
- GET /:kind/:id/prints/:task/pdf：鉴权后返回 PDF；未生成或已过期时拒绝获取。

上述路径均以 /api/registration 为前缀，沿用模拟会话、身份及对应记录读取权限。生成记录按入口和记录隔离，页面不展示打印范围提示。实际委托入口对应全部样品、样品入口对应当前样品的 PDF 内容由未来后端根据对象类型和单号决定；当前仅保留基本信息模拟 PDF，每个所选联次一页，不枚举或拼装真实样品内容。

普通任务模拟排队 5 秒、转换 5 秒；长队列排队 45 秒。前端不提供模拟场景设置。新任务以 70% / 15% / 10% / 5% 的概率模拟正常生成、较长排队、失败和过期，任务创建后结果保持固定；scenario 仅供自动化接口测试固定场景使用。任务及基本预览信息保存在服务端内存，同入口、同记录和同选项的运行中任务复用；任务结束后再次生成创建新任务。刷新或离开不会取消，服务重启和会话过期清空。生产接入需替换为持久化任务、真实转换服务和后台模板配置。


### 检测依据与委托单位输入

检测依据仅可从当前检测方案的标准列表多选，最多 50 项。以多行文本框回填完整编号和名称，只允许编辑相邻依据之间的分隔内容，每处 1–2 个标点、符号、空格或换行；增删或更换标准通过列表完成。编辑时可以暂时清空一个分隔位置，但填写分隔符后才能保存。

`details.testBasisSeparators` 按相邻所选 ID 顺序保存分隔符数组（长度为标准数减一，最少为零）。`test-bases/resolve` 接收可选 `separators`，省略时默认中文分号，返回解析文本及实际分隔数组。保存时后端验证分隔符和标准权限并重新生成 `details.testBasis`，不信任客户端填写的依据内容。重新选取时保留未改变的相邻项分隔符，新相邻项使用中文分号；切换检测方案清空原选择。

委托单位使用多行文本框，可直接编辑和换行。多选单位确认后使用中文分号“；”分隔回填；重新打开列表时按换行或分号匹配已选单位。保存保留用户输入的文本内部换行，查看模式只读。

### 样品通用项目信息补充

所有方案均显示 `details.productCode`（编号）、`manufacturer`（生产单位）、`productionDate`（生产日期）、`specification`（规格型号）、`requestedTestDate`（要求试验日期），样品数量复用样品的 `quantity`，不另存重复数量。编号为用户填写的产品编号，不替代系统样品编号。

商标图片通过 `details.trademarkImage`（name/dataUrl）随表单保存，支持 PNG、JPEG、WebP，单张最大 2 MB，可预览、下载、更换或删除。正式接入时可替换为上传文件接口及文件 ID。

### 样品报告设置

`GET /api/registration/samples/report-settings-config` 返回独立配置：`version`、`options`、`defaults` 和 `combinations`。四个设置键为 `formatId/titleId/languageId/layoutId`；每类字典由稳定 `id` 与 `label` 组成，允许组合为四个 ID 的完整记录。当前模拟配置集中在 `server/sampleReportSettings.ts`，不存在前端按报告名称判断的特殊规则，也不提供配置管理界面。

报告标题为示例检测、空调中心；报告格式为产品、抽样、工程、检验、校准。语言为中文、英文；首页版式为标准版、扩展版。初始规则：检验与校准仅示例检测，校准仅中文，扩展版仅产品与抽样。新增默认格式及标题为空，语言为 `zh`，版式为 `standard`；默认值来自配置。新建样品在“公共信息”后展示独立报告设置，检测类别不参与联动。

`details.reportSettings` 保存四个 ID，替换旧 `reportFormat/reportTitleId/reportTitleCn/reportTitleEn`；`reportForm` 仍是委托方要求中的报告形式。未选项为 `''`，允许不完整设置，但必须能匹配至少一个允许组合。选择按格式、标题、语言、版式的顺序约束下游；有效值保留，无效值在可选项唯一时自动选取，否则清空，自动调整用 Toast 提示。已有记录初始化只恢复值，不自动修正；失效项明确标记并阻止保存。

保存样品请求在 `{ input, version }` 之外增加可选 `reportConfigVersion`，当前表单始终提交已加载的配置版本。后端再次校验四个 ID 及允许组合；非法选择返回 422，并标记 `error.fieldErrors.reportSettings`。配置版本不一致返回 409，使用同一字段标记。前端收到该标记后仅刷新报告配置，保留全部表单输入，不自动再次提交；配置读取失败在报告设置区提供重试，无本地规则回退。真实报告抬头及英文全称由后台模板配置，前端不推导或编造。不迁移历史模拟数据。

### 生产厂家选择

`POST /manufacturers/query` 接收 `code/name/type/page/pageSize`。代号与名称按包含匹配，类型精确匹配；返回当前页 `items/total/page/pageSize` 及当前权限范围内的 `types`。每项包含 `id/code/name/type`。使用独立模拟厂家目录，按身份部门限制访问，每页支持 5、10、20 条。

生产单位选择框显示厂家（产地）代号、名称、类型，支持跨页多选、全选本页及取消本页选择。查询和翻页保留待选内容；确定后按选择顺序用中文分号连接名称，写入 `details.manufacturer`；返回不回填。再次打开按当前文本恢复名称匹配，生产单位仍允许用户直接编辑。查询区、分页及按钮固定，中间列表滚动。

子项目名称下拉选项由 `GET /samples/defaults` 的 `subprojectOptions` 提供，每项包含 `name/accountingDepartment/businessCategory`。用户切换子项目名称时，自动填入该选项的核算部门和业务三级分类；两者均为可编辑文本框。打开修改或查看对话框不会重新带入默认值，保存使用用户最终编辑的内容。当前选项及关联资料采用模拟数据。

### 样品附件

样品与委托分别保存各自的 `attachments`，新建样品不复制委托附件。`POST /samples/:id/attachments` 接收 `{ version, file }`，`DELETE /samples/:id/attachments/:attachmentId` 接收 `{ version }`；返回更新后的样品及版本。复用附件格式、20 MB 上限、内容校验、部门范围与版本检查；已完成、已作废或无样品编辑权限时禁止上传和删除。详情接口返回附件供授权用户下载，列表摘要不包含附件内容。样品表单保存接口忽略客户端传入的 `attachments`，附件由专门接口管理。

委托登记的样品附件由样品行菜单末尾的“附件管理”进入，复用委托附件对话框，支持上传、下载及确认删除；新增、查看、编辑样品页面不再显示附件区。上传、删除仅更新对话框及样品行版本，不重新查询背景列表。状态、权限、20 MB 上限、加载保护及失败处理沿用现有规则；已完成、申请作废及已作废样品仅支持查看、下载。合同评审、委托查询、委托更改等其他工作区的原附件入口不变。当前附件保存在模拟服务会话中。

### 样品列表列与摘要

委托查询（`workspace: query`）使用独立的 29 列，顺序、默认显隐与样品表单字段对应见 [委托查询样品列核对](docs/commission-query-columns.md)。`POST /samples/query` 为该工作区补充查询摘要字段；`POST /samples/export` 按相同 29 列导出。新增列默认隐藏，其他工作区不增加这些查询专用列。下一状态、样品批号、样品资料列已移除。外部ERP合同编号读取后台独立提供的 erpContractNumber，与 commissionInfo.erpContract（外部ERP项目编号）区分，缺失时不回退到项目编号。尚未实现的折扣/实际价格显示“—”。

样品列表与导出按以下 16 列顺序显示：样品编号、委托编号、报告编号、委托经办人、样品登记人、样品类型、样品/工程名称、检测参数、数据状态、检测方案、委托单位、项目名称、标准价格费用、折扣价格费用、实际价格费用、附件。委托登记和合同评审使用同一列配置。勾选与操作列另行保留；默认显示样品编号、报告编号、样品登记人、样品类型、样品/工程名称、检测参数、数据状态、委托单位共 8 列，检测方案、项目名称、附件默认隐藏。样品编号固定保留，其他列可通过“显示列”勾选，并支持恢复默认。`sColumns` 保存按白名单校验的列标识，按既定顺序显示；与委托列配置独立，刷新和详情/表单返回均恢复。列显隐不重新查询、不清空勾选或分页，导出仍包含全部列。检测参数超过 20 个字符显示省略号，title 保留全文，导出不截断。表格内部横向滚动，不缩小字体或造成整页溢出。

`sampleType` 为独立样品类型，模拟数据含原始样品、英文报告样品、分项/阶段性报告样品、补充报告；`dataStatus` 为独立样品委托单流程状态，模拟数据含委托登记中、委托登记完成。新建由服务端初始化为原始样品、委托登记中，二者不取检测类别 `category` 或登记状态 `status`，前端不能通过表单保存覆盖。登记状态使用 pending（未完成）、completed（已完成）、voided（已作废），不据此推导委托登记流程状态。

委托经办人及项目名称取样品持有的委托信息副本；检测方案 `testPlan` 取 `details.testPlan`，不使用项目名称代替。样品登记人取样品 `owner`；检测参数取 `projects`；样品/工程名称取样品 `name`。附件列根据样品自身的 `attachmentCount` 显示“有”，没有附件留空；上传或删除后同步更新当前行标记及版本，不重新查询背景列表。不包含签订技术服务合同列。标准价格费用取 `details.standardPrice`，另两项计算费用来源未定返回 `null`；其他空值展示“—”，金额保留两位小数、零显示 `0.00`。列表摘要仅增加附件数量，不携带附件内容或整个样品表单，继续使用服务端分页。导出使用同一字段顺序及格式，保持查询结果与已选记录两种范围。

### 委托与样品列表统一排版

两张表按相同的列配置规则展示：名称、项目名称和单位列使用模板换行样式并保留 160px 最小列宽；编号、日期、状态、人员、类型及金额保持单行，金额右对齐。检测参数保留 20 字符省略显示及全文 title。开启更多列或使用小屏时，仅表格容器横向滚动，保持正常字号。列显隐、默认列及导出内容不受排版调整影响。

委托列表摘要新增 `sampleCount`，由后端统计关联样品数；无样品时禁用打印，直接请求生成也被后端拒绝。委托和样品入口提交对应的对象类型、单号及打印选项，生成记录按入口和记录隔离。实际 PDF 内容选择交由后端，当前保留基本模拟预览；详见“委托打印模拟接口”。

### 样品列表操作

单行菜单提供查看、编辑、打印、完成／取消完成、作废，末尾为附件管理，统一使用模板图标。`POST /samples/:id/actions` 使用现有版本号协议，操作 ID 为 `complete`、`uncomplete`、`void`；作废须填写原因并确认，保留记录与操作记录。已完成须取消完成后才能编辑或增删附件；已作废仅可查看，登记菜单显示查看及只读附件管理，不能勾选参与批量修改；全选跳过作废样品。直接访问打印接口也会拒绝，不能再次编辑、完成或取消完成。服务端重新校验状态、权限和版本，表单保存不能直接修改登记状态。原接收、退回、重新提交操作已从本登记模块移除。

批量修改位于样品列表顶部，与新增样品同一工具栏。仅当勾选样品属于同一委托且均未完成时启用；未勾选、跨委托、存在已完成或作废记录时禁用并显示原因。查询、翻页及切换身份清空选择，避免操作隐藏记录。

### 登记列表工具栏

模拟委托的初始 `commissionDate` 按模拟会话创建当天及之前 13 天生成，确保最近一年默认查询有记录可展示；初始样品的委托信息快照同步复制这些日期。缺失日期的记录仍不匹配日期范围，不使用登记时间替代。

## 合同评审工作区

入口 `/commissions/review`。合同评审和委托登记的页面入口分别为 `ContractReviewView.vue`、`RegistrationView.vue`，共用 `RegistrationWorkspace.vue`，查询、列配置、分页、导出及关联样品范围保持一致。委托菜单为查看、编辑、完成／取消完成，不提供委托打印及新增入口；样品菜单为查看、编辑、打印、开始评审／撤销评审、作废（提交申请）。作废申请中及已作废样品仅可查看。所有返回链接保留所属工作区及查询参数；评审工作区的新增路由跳回列表。

样品详情及列表摘要新增 `reviewStatus: 'unreviewed' | 'reviewed' | 'approved'`，缺省视为未评审。它独立于登记 `status`，评审操作同步更新 `dataStatus`、版本和操作记录，保持登记完成状态。列表范围由后端控制，仅返回待评审、评审中阶段的样品；前端不按登记状态过滤返回记录或判断能否评审。当前模拟后端用已完成登记、尚未通过评审且未作废的样品模拟这一队列，评审／撤销评审仍发生在此阶段内。操作仍使用 `POST /samples/:id/actions`，新增 `actionId: 'start-review' | 'review' | 'unreview'`，必须提交当前 `version`；服务端要求登记状态为 `completed`。已评审样品取消登记完成前须先撤销评审，避免登记与评审状态矛盾。

评审工作区允许编辑未作废、尚未评审的样品（包括登记已完成样品）。评审后锁定普通编辑、附件增删及批量修改，撤销评审后恢复。委托单完成／取消完成和编辑规则沿用登记页面。权限沿用现有委托／样品写权限和数据范围，并由后端重新检查。

样品列表查询、导出（包括已选 ID）、普通保存、附件增删和批量修改的 context/source/save 请求增加可选 `workspace: 'review'`，省略时保持原登记行为；样品查询及导出由后端在分页和总数计算之前应用场景范围，与用户查询条件取交集；该参数仅声明业务场景，不授予权限。HTTP 路径仍使用 `/api/registration`，两个页面操作同一份数据。评审工作区不允许新增；普通表单输入不接受直接修改登记或评审状态。批量修改仍要求同一委托、全部目标可编辑且版本匹配，不修改原委托单。

接口回归在 `registrationApi.test.ts`，浏览器流程回归在 `contract-review.spec.ts`，涵盖独立评审、未完成登记拦截、编辑及附件锁定、撤销恢复、版本冲突、权限、跨委托限制、工作区返回及手机深色布局。


### 评审样品详情与合同评审内容

合同评审列表的“开始评审”进入 `/commissions/review/samples/:id/assess`，复用样品完整只读表单，底部按顺序提供返回（浅色次要按钮）、评审（主色按钮）。普通查看页不显示这些操作。评审弹窗包含六项满足要求检查（初始勾选）、检验依据授权、CMA、CNAS、其他说明；取消不提交，失败保留草稿。底部为取消、不通过、通过。作废仅保留在列表菜单，使用既有原因确认和状态校验。

`POST /samples/:id/actions` 的 `review` 操作必须携带 `review` 对象，结构定义在 `contractReview.ts`，经后端逐项校验后保存为样品 `contractReview`。通过必须六项全部为真，并完成当前样品版本的合规校核及阅读确认；不通过允许未全部勾选；“其他”未勾选时不保存其他说明。普通表单保存不允许更改评审内容。撤销后保留上次评审内容供下次打开回显。

列表数据状态由后端更新：登记完成为“完成登记”，进入评审样品详情时即为“合同评审中”，撤销评审恢复“完成登记”；登记状态 `completed` 在评审和撤销时保持不变。取消登记完成恢复“委托登记中”。查询、导出和刷新均读取同一状态，数据状态筛选同步提供这些选项。未完成登记和作废样品仍由后端排除在评审列表范围之外。

点击“开始评审”进入专用详情时，前端提交 `start-review`，模拟后端立即更新状态并锁定普通编辑；重复进入或刷新不会重复更新版本和审计。普通查看不触发此操作。`review` 仅在开始评审后校验并保存对话框内容及结论，然后由后端更新状态。取消对话框、返回列表不撤销已开始的评审。菜单同时显示“开始评审”和“撤销评审”，未开始时撤销项禁用；开始后可撤销并恢复“完成登记”。开始请求失败显示错误并支持重试，不继续展示可操作的评审表单。

合同评审提交 `review.decision: approved | rejected`，不接受缺失或其他值。通过仅要求六项满足要求全部勾选，不要求备注授权项；后端逐项复核，不信任按钮禁用。通过置 `reviewStatus=approved`、`dataStatus=评审完成`，退出后端评审队列；不通过置 `reviewStatus=unreviewed`、`dataStatus=完成登记`，恢复编辑并保留本次内容供重新评审。两者保留登记状态 completed。取消无写入；提交成功返回列表，失败保留草稿。

合同评审样品工具栏首位提供“快速评审”，仅单选时可用。读取当前样品版本并提交 start-review 后直接复用评审对话框，无须进入详情；提交、取消后重新查询列表状态。按钮不在委托登记工作区显示。加载失败可再次点击重试，切换选择、路由或身份时忽略过期响应。


### 合规校核与阅读确认

普通评审和快速评审共用对话框：是否满足要求、备注授权、合规校核三个紧凑分区；移除备注内容 textarea，历史 notes 仍兼容并由后端保留。底部为取消、不通过、通过。模板使用 Cards、Left Border Alerts 和 Loading Buttons，三个分区恢复初始紧凑标题栏：card-header 搭配 py-2 px-3，card-title 搭配 fs-14 和原生标题行高；校验按钮使用 my-n2，使三个标题栏保持等高，加载时不撑高。对话框随内容收拢，不强制撑满视口；内容超出可用高度后，桌面端校核结果区独立滚动，窄屏或低高度视口统一随 modal-body 滚动，避免嵌套滚动。提示文本自然换行，阅读确认和底部操作始终位于滚动区域之外。

`POST /api/registration/samples/:id/review-check` 接收 `{ version, reviewOptions }`（六项要求、四项授权及有效的其他说明），仅允许有写权限且处于合同评审中的样品，使用约 1.5 秒异步延时模拟校核。返回 `{ id, sampleId, sampleVersion, checkedAt, reviewOptions, messages: [{ tone: 'info' | 'warning', text }] }`。本期仅示例信息，不代表正式合规规则；warning 也不阻断评审。校核不更新样品版本、审计或工作流状态。

校核结果存于 Node 会话内的独立存储，按操作者和样品维护最新标识。新请求开始即淘汰旧结果；异步完成时再次校验样品版本和状态，较早请求不能覆盖新请求。通过请求在 `review` 内增加 `checkId` 与 `readConfirmed: true`，后端校验归属、版本、最新标识、确认值及六项要求，并逐项比对提交选项与校验快照，选项变化则拒绝通过且不改变样品状态。结果正文和确认人不接受客户端赋值，存入 `contractReview.compliance` 的 result、confirmedBy、confirmedAt 来自后端。不通过无需校核；如存在与当前选项一致的有效结果则一并保存证据；未勾阅读确认时记录 readConfirmed=false，不写确认人/确认时间。失效结果不作为证据保存，也不阻断不通过。

打开对话框不自动校核、不恢复阅读确认；重新校核立即清除旧结果与确认。要求、授权和其他说明可直接编辑；修改任一有效字段立即清除结果与阅读确认，修改后须重新校验才可通过。校核中修改会中止请求并忽略过期结果，程序更新这些字段时也会清除校验。保存和刷新样品期间禁用编辑。校核等待禁用通过和不通过，允许取消。失败保留草稿并允许重试/不通过。普通提交失败保留草稿；版本冲突清除校核与确认，需用户点击刷新样品，再重新校核和阅读确认，不自动重写勾选或提交。关闭、换样品、换身份、离开页面均丢弃过期响应。

合同评审页样品查询的数据状态选项为全部、合同评审中、合同评审完成；完成选项提交既有值 `评审完成`。默认仍为当前评审队列，显式查询完成状态时由模拟后端返回已通过评审的样品，列表及导出范围一致。委托登记页选项不变。

### 样品作废申请
现有样品 `void` 操作表示提交作废申请，不直接作废。后端要求申请原因、权限和版本有效，从 pending/completed 转为 void_pending，dataStatus 为“作废申请中”，保存 voidApplication 的申请原因、申请人、申请时间及申请前 status/dataStatus/reviewStatus，记录“提交作废申请”事件。申请中记录仅可查看，不能重复申请、编辑、完成、评审、修改附件或打印；合同评审待办队列由后端移除该记录。历史 voided 状态仍保留。本次不实现审批操作，后续作废审批可按 void_pending 查询并读取申请信息。

### 委托查询与外部ERP推送
`/commissions/query` 使用独立入口 CommissionQueryView 和公共 RegistrationWorkspace 查询模式，沿用双列表、查询、分页、列设置、导出、关联筛选。委托菜单仅查看/打印，样品菜单仅查看/打印/重新推送外部ERP；作废申请中及已作废样品仍仅可查看，无样品委托禁用打印。查询范围由后端在当前数据权限内提供，区别于合同评审待办队列；样品请求/导出带 workspace=query。详情、打印沿用已有组件，并保留委托查询的返回路径与筛选参数。无新增、编辑、批量修改或评审入口；查询编辑路由转详情，后端拒绝 query 模式保存、附件修改和批量修改。
`POST /api/registration/samples/:id/erp-push` 接收 `{version, requestId}`。后端重新检查样品数据范围、写权限、版本及作废状态，再将样品 ID、编号、版本、请求人和时间写入当前会话的模拟消息队列，返回 202 与 `{id,sampleId,sampleCode,sampleVersion,status:'queued',queuedAt}`。不调用真实外部ERP接口、不声称已送达，也不修改样品业务状态/版本。相同操作者和 requestId 重试返回同一消息，不重复入队；同标识改用其他样品或版本则拒绝。前端防止并发重复点击，失败可重试；重试沿用标识，离开页面/换身份时忽略过期响应。

查询表单按钮统一不提供“重置”，包括列表查询及合同、单位、厂家、检测方案、检测依据选择弹窗。表格工具栏按钮文字统一为“导出”“显示”，菜单内的导出范围和列配置“恢复默认”保留。

委托查询样品内容筛选扩展 `searchField=commissionOwner|reviewer|customer|name|contact|manufacturer`，只在 `workspace=query` 下接受。委托经办人、委托单位、委托人分别读取样品 `commissionInfo.owner/customer/contact`，工程/产品名称读取样品 `name`，生产单位读取 `details.manufacturer` 的完整可编辑文本；不读取原委托实时值。合同评审人读取最新开始、通过或不通过评审记录的操作者，最新相关记录为撤销评审时为空；无相关操作记录的历史样品使用已保存校核确认人。列表与导出采用同一匹配逻辑，忽略大小写、包含匹配，与状态、类型、日期、权限及委托范围同时满足。

字段核对：委托经办人对应样品“委托信息 → 业务办理信息 → 经办人”，委托单位和委托人也来自样品的委托信息。查询选项“工程/产品名称”对应当前表单“公共信息 → 工程/产品名称”，并非“项目名称”。生产单位对应“项目信息 → 生产单位”。样品登记人是后台创建记录时保存的操作者元数据，不是表单输入项；合同评审人也不是表单输入项，目前从评审操作记录（历史记录可用校核确认人）取得，不能当作已存在的独立评审人表单字段。

## 委托查询：委托高级查询

高级弹窗仅在委托查询页提供，与页面“查询内容”共用同一字段定义（排除聚合选项“全部”）：委托编号、样品/工程名称、委托单位、委托人、委托经办人；另含独立的委托状态和可选委托日期。另外补充合同号、工程备案编号、工程编码（交易中心），分别提交 contract、projectRegistrationCode、projectTradingCode。

页面查询与高级查询独立。页面“全部”对上述五个文本字段按 OR 匹配同一个关键词；选定某项时只匹配该字段。高级查询分别填写八项，各非空条件按 AND 匹配，空字段不限制。OR／AND 匹配均由后端处理，前端仅收集并提交参数，不过滤返回记录。状态、日期范围仍是各自查询内部的约束，不与文本条件使用 OR。文本查询均忽略大小写、包含匹配。

高级查询只发送 `commissionAdvanced`（八个文本字段，键与委托模型一致）、自身状态及可选日期，不携带页面条件。提交页面查询切回页面条件。高级日期默认不启用，预填客户端一年前至当天；勾选后必须选择完整范围，日期过滤仍按委托日期且包含起止当天。后台校验字段白名单、类型及最多 200 字，样品接口拒绝委托高级条件。

URL `cQueryMode=advanced` 表示当前结果来自高级查询，`caCode/caName/caCustomer/caContact/caOwner/caContract/caProjectRegistrationCode/caProjectTradingCode/caStatus/caUseDate/caFrom/caTo` 保存独立高级条件。普通条件参数仍单独保留；取消/关闭丢弃弹窗未提交修改，重新打开恢复上次提交值。两种查询共享当前列表的分页和排序，提交查询回到第一页并按既有规则清除委托选择，刷新关联样品；导出查询结果、重试、详情返回与刷新均使用当前生效的条件。高级按钮高亮表示当前使用高级查询。复用模板栅格、输入控件、日期范围和弹窗，无新增 CSS。样品高级查询详见下节。


## 委托查询：样品高级查询

仅委托查询页提供，普通表单和高级弹窗各自保存条件，最后提交的表单决定当前样品查询条件，继续受“当前委托／全部委托”范围与权限约束。普通查询不携带高级条件，高级查询不携带普通输入。前端只提交参数，匹配和 AND 组合、排序、分页及导出全部由服务端处理。

`sampleAdvanced` 包含可选文本条件：
- `commissionCode/reportCode/code`：样品保存的委托编号、报告编号、样品编号。
- `contract/projectRegistrationCode/projectTradingCode/erpContract/projectName`：样品 `commissionInfo` 中的合同号、工程备案编号、工程编码（交易中心）、外部ERP项目编号、项目名称。
- `commissionOwner/customer/contact`：样品 `commissionInfo.owner/customer/contact`；不读取原委托的当前值。
- `name/owner`：工程/产品名称、样品登记人。
- `reviewer`：沿用普通查询的合同评审人来源（最近相关评审操作，撤销后为空；历史记录使用校核确认人）。
- `manufacturer/specification/inspector`：`details` 中的生产单位、规格型号、指定主检人。
- `projects`：检测项目（按样品项目列表文字查询）。

各非空文本字段忽略大小写、包含匹配，并同时满足；空字段不限制。弹窗独立提供数据状态、样品类型和可选委托日期，分别使用既有 `dataStatus/sampleType/commissionFrom/commissionTo` 参数。日期默认不启用，预填客户端一年前至当天；启用后要求完整范围，包含起止当天，缺少委托日期的记录不匹配。后台校验高级条件为对象、仅接受白名单字符串且不超过 200 字；仅样品接口 `workspace=query` 接受此对象，列表和导出共用匹配逻辑。

截图中的检测人员 1/2、校核/审核/批准人、结构部位及建设/施工/监理单位本次不引入。流程日期与结论已作为后续业务模块的预留字段接入查询，详见下节。指定主检人不视为两名实际检测人员；项目名称与工程/产品名称分别取委托信息和样品公共信息；外部ERP合同编号采用现有的外部ERP项目编号名称。

`sQueryMode=advanced` 标记生效模式，文本字段以 `sa` 加首字母大写的键保存 URL（如 `saCode/saProjectName/saSpecification`）；`saDataStatus/saSampleType/saUseDate/saFrom/saTo` 保存其余独立条件。查询回到第一页并清除样品勾选；取消关闭丢弃未提交修改，翻页、错误重试、详情返回、刷新和导出保留当前生效条件。普通与高级查询分别保留已提交条件。使用既有模板三列栅格、滚动弹窗和固定底部操作区，无新增 CSS。


### 样品流程日期与结论查询

样品高级查询增加检测开始日期、检测完成日期、校核日期、审核日期、批准日期、报告日期、制作日期，和原委托日期一起展示于“日期条件”区域。每个范围独立勾选，默认不启用、预填客户端过去一年；取消勾选后保留范围草稿但不提交。结论选项为“全部、合格、不合格”，全部不提交条件；另外两项分别提交稳定值 `qualified/unqualified`。

样品查询/导出在 `workspace=query` 下接受可选 `sampleWorkflow: { dates?: { testStartDate?: { from, to }, testEndDate?: { from, to }, checkDate?: { from, to }, auditDate?: { from, to }, approvalDate?: { from, to }, reportDate?: { from, to }, preparationDate?: { from, to } }, conclusion?: 'qualified' | 'unqualified' }`。后台验证对象、白名单、结论枚举、完整且有效的日期范围，并与其他高级条件使用 AND 匹配；日期包含起止当天，结论精确匹配。无对应事实的记录不匹配启用的条件，不会从创建时间、要求试验日期、评审结论等其他字段推导。

样品模型预留可选 `workflow`，其中日期以相同字段键存储 `YYYY-MM-DD`，结论使用相同枚举。今后的检测、校核、审核、批准及报告模块负责写入这些事实；本次不实现这些流程、不填充模拟结论或日期、不增加样品编辑字段、不迁移历史记录。测试夹具单独注入事实用于验证边界和导出一致性。

URL 使用 `saConclusion` 保存结论；每个流程日期使用 `sa<Key>Enabled/sa<Key>From/sa<Key>To`（例如 `saTestStartDateEnabled=1`）。仍与普通查询独立，取消丢弃未提交更改，刷新、返回、分页与导出保留已提交条件。


### 高级查询提交生命周期

委托与样品高级查询均先请求服务器，成功后才更新生效条件、URL 和列表并关闭弹窗；返回零条记录也视为成功。提交期间显示“查询中…”，禁用输入、关闭、取消和重复提交。失败时弹窗显示错误并保留草稿，用户可修改后再查询或重试，原列表及生效条件保持不变。成功响应直接用于列表，不因 URL 更新再次请求相同条件。离开页面、切换身份时中止待处理请求并忽略过期结果。后续翻页、刷新及导出仍使用已成功提交的条件。


### 模拟查询延时

委托和样品 `POST /query` 在模拟后端默认异步等待 2000 ms 后执行查询并返回，适用于普通查询、高级查询、初次列表加载和翻页。配置集中在 `server/registrationApi.ts` 的 `registrationQueryDelayMs`；设置为 0 可关闭，`createRegistrationMiddleware({ queryDelayMs })` 可覆盖（接口单元测试使用 0）。延时不会阻塞其他请求，客户端断开时清理定时器并停止后续查询。导出、详情和保存等接口不使用此延时，原评审校核延时保持独立。

开发及预览服务器也可用服务端环境变量 `LIMS_MOCK_QUERY_DELAY_MS` 覆盖延时（0～30000 毫秒，重启服务后生效）；未设置时仍默认 2 秒。自动化浏览器测试自行启动的服务器默认关闭演示延时；运行 `query-delay.spec.ts` 时显式设置该环境变量为 2000，验证真实后端等待和弹窗加载状态。前端不接收或控制此延时配置。


## 委托更改

`/commissions/changes` 使用一张公共表格，提供 15 列，原项目名称列改为检测方案（取样品 details.testPlan，默认隐藏），最后增加附件列（默认隐藏，有附件显示“有”，没有留空，上传或删除后同步更新而不刷新列表）。默认显示样品编号、报告编号、样品类型、样品/工程名称、检测参数、处理结果、问题来源、问题提交人、问题提交日期九列，其余可通过显示菜单开启；空白无名称列不引入。问题提交日期默认为最近一年，问题来源默认全部、处理结果默认问题处理中、样品类型默认全部，按委托编号升序排列。筛选、排序、分页、显示列和编辑返回地址保存在本页 URL；菜单仅有更改、完成。

- `POST /api/registration/samples/changes/query` 接收 `from/to`（问题提交日期，包含边界）、`source/result/sampleType`、`sort/direction`、`page/pageSize`（10/20/50，默认 10）及可选 `ids`，返回列表分页。模拟后端先检查部门和读取权限，再限定 `dataStatus=委托更改中` 且未作废的样品，之后组合筛选、排序、分页。沿用列表模拟延时。
- `POST /api/registration/samples/changes/export` 使用同一查询结构和范围，导出全部符合条件或勾选的样品；纯列配置与前端共用。
- 编辑页 `/commissions/changes/samples/:id/edit` 复用样品表单、附件、保存校验、版本冲突和离开提醒。更新/附件接口提交 `workspace: changes`，后端只允许当前处于委托更改中的样品。不能新增样品或修改原委托单，既有检测方案仍不可更换。
- 完成沿用 `POST /samples/:id/actions`，提交 `actionId: complete-change` 和版本；后端校验权限、状态及版本后原子更新当前样品为 `status=completed`、`dataStatus=完成登记`、`reviewStatus=unreviewed`，记录“完成委托更改”审计事件，处理结果为问题已处理并保存处理人和时间。该样品退出更改队列并可进入合同评审；原委托单及同委托其他样品不变。普通登记和合同评审操作不能绕过更改流程。

问题元数据位于样品的可选 `commissionChange` 中，仅由后端维护，普通样品更新不接收该字段。现有演示样品 61、63、66、69、70、72、75、78 提供示例问题（70 属于另一部门）；不改变原有样品总数。问题来源为“问题处理、报告更改”，正式问题上报/受理流程后续接入。本期不新增问题申请入口。


## 作废审批

`/commissions/cancellation-approval` 使用单列表，查询条件为申请日期（默认近一年）和数据状态（全部、申请中、申请通过、申请不通过，默认申请中）。每页 10/20/50 条，默认 10；查询、排序、分页和显示列保存至 URL。提供 12 列，报告编号后增加检测方案（取样品 details.testPlan，默认隐藏），默认显示审批结果、委托编号、样品编号、报告编号、样品/工程名称、申请人、申请原因、申请日期，其余通过“显示”开启。申请原因及审批不通过原因截断预览、title 显示全文，导出不截断。

- `POST /api/registration/samples/cancellation-approvals/query` 接收 `from/to/result/page/pageSize/sort/direction/ids`；按服务端部门范围、实际作废申请筛选和分页，日期包含首尾当天，沿用模拟查询延时。
- `POST /api/registration/samples/cancellation-approvals/export` 使用相同筛选与权限范围，导出全部匹配或选定记录的 12 列。
- `POST /api/registration/samples/:id/cancellation-approval` 接收 `version/decision/reason`。管理员及批准角色可审批；其他可读身份仅可查询，不能通过直接接口越权。服务端检查申请待审批状态、权限、范围和版本，重复审批被拒绝。
- `approved` 将样品设为 `voided / 委托已作废`；`rejected` 必须填写不通过原因（最多 500 字），严格恢复申请时保存的 `previousStatus/previousDataStatus/previousReviewStatus`。不接受客户端指定恢复状态或审批身份，原委托单不变。
- `voidApplication` 保留申请信息，并增加 `decision/approvedAt/approvedBy/rejectionReason`，同时写入审计、递增样品版本。无 decision 的既有申请按待审批兼容。审批结果与样品的数据状态分开显示；已审批记录通过“查看审批结果”只读查看。
- 对话框顺序为取消、不通过、通过；提交中禁止重复提交，失败保留原因，关闭和切换身份清除草稿并忽略过期响应。查询失败支持重试。

示例样品 52、60、42 为申请中，54 为申请通过，57 为申请不通过（42 属于另一部门）；记录总数不变。登记与合同评审提交的新作废申请会直接进入此队列。

## 样品入库查询与方案筛选

`/samples/inbound` 使用全宽公共表格，上方按样品编号、数据状态、委托日期及检测方案查询。页面不提交站点筛选，旧 URL 中的 `site` 也不参与查询或导出。日期默认为过去一年，状态默认为样品入库中；分页为 10/20/50。条件、排序、分页、显示列保存在 URL，点击样品编号查看详情后返回保留。查询清空行勾选并回到第一页，等待时保留不可操作的浅色旧行。行菜单为“入库、撤销入库”，按当前状态及权限禁用不可用操作。点击后使用“取消、确认”对话框，暂不增加入库信息表单；提交成功重新加载列表，失败保留对话框，版本冲突或状态变化提供刷新入口。

- `POST /api/registration/test-plans/selection` 接收 `selection: { groupIds, planIds, excludedPlanIds }` 及可选 `toggle: { kind: 'all' | 'group' | 'plan', id, checked }`。服务端按身份可访问的完整方案目录展开分组，返回规范化范围、已选数量、前三个名称及分组全选/半选状态；同时返回当前身份可访问的最小目录索引 `catalogue`（分组 ID、方案 ID、所属分组、名称，以及适用时的有样品方案 ID），用于前端本地计算勾选状态。界面仅在打开时调用，接口保留可选 toggle 参数以兼容已有调用；范围内任意未知或越权 ID 均拒绝。
- `POST /api/registration/samples/inbound/query` 接收 `code/status/site/from/to/plans/page/pageSize/sort/direction`，返回分页、站点选项和方案摘要。多个方案使用 OR，与其他字段使用 AND；委托日期含起止当天，启用日期条件时缺失日期不匹配。仅查询服务端保存的“样品入库中、样品入库完成”且非作废/作废申请中的记录，先限定部门范围再筛选。沿用后端模拟延时。
- `POST /api/registration/samples/inbound/export` 使用相同条件及可选 `ids`，导出所有匹配或选中的记录，文本不截断。
- `POST /api/registration/samples/:id/inbound-action` 接收 `action: 'receive' | 'undo'` 和当前 `version`。后端验证写权限、部门范围、版本及入库状态；入库将“样品入库中”更新为“样品入库完成”，撤销做相反变更，拒绝作废、作废申请中和其他流程阶段的记录。成功增加版本并记录操作者、时间与操作，保持登记、评审和入库信息不变。失败不改变记录；前端不自行维护业务状态。

新操作日志使用“撤销入库”，既有日志不迁移。预加载遵循 Tabler 模板：默认关闭，不显示动画或替代文字；开启时复用 `#preloader > #status` 和模板转圈样式，在浏览器 `load` 事件后隐藏，进入工作空间不重复播放。切换预加载选项自动关闭设置抽屉，启用预览约 1000 毫秒后结束。沿用项目既有主题持久化；启动异常仍显示可重试的错误反馈。表格查询和操作提交各自跟随请求显示等待状态，不受该开关影响。

右侧抽屉复用 `RegistrationTestPlanBranch` 的分页数据源及图标；`multiple/selection/toggle` 提供多选接入，原 `selectedId/select` 单选保持不变。搜索、翻页及展开不清除选择；分组选择覆盖全部下级方案，排除项单独保存。勾选、取消勾选及清空仅更新抽屉内草稿，即时计算整组、全选和半选状态，不发起选择请求。底部仅保留关闭，关闭/Esc/点击遮罩时将草稿回填页面查询条件；页面点击查询才向后台提交并校验范围、刷新列表。清空范围表示不限制方案，顶部最多显示两个名称与“另 N 项”。手机端抽屉全宽，Bootstrap 负责焦点约束及 Escape 关闭。

`POST /api/registration/test-plans/query` 默认返回当前用户可访问的完整分类及方案，包括零条目的节点；每个节点附带 `inboundSampleCount`，表示对应入库样品单的数量，分类汇总其下级方案的数量。计数不依赖当前表格页、日期、站点或已选方案。抽屉按需加载分类或展开分组的全部分页后缓存，由前端按数量过滤并分页，默认仅显示有样品的节点；“全部显示／仅显示有样品”只切换本地显示，不重新请求服务端。搜索仍由服务端检索完整目录。显示范围切换保留已有选择及展开状态，隐藏项仍计入已选数量；勾选分组使用首次加载的授权目录索引计算完整下级范围，无需先展开树节点。新增样品单选界面保持原有服务端分页，不过滤零条目节点。切换身份后恢复默认显示范围。

首次打开抽屉加载授权目录及已有选择，加载失败提供重试入口。当前页面缓存成功加载的授权目录和树节点查询结果；再次打开抽屉、设备方案选择或原单选方案对话框时复用缓存，未展开过的分组按需加载。缓存不保存选择草稿，重开时使用页面或表单的当前选择。分页和查询参数变化不清空缓存；离开页面、刷新或切换身份/权限后重新加载。失败、取消及失效请求的结果不写入缓存。勾选过程不显示“正在更新选择”。关闭时中止尚未完成的初始化请求并忽略过期响应；初始化未完成时保留页面原有选择。切换身份或离开页面时中止请求、丢弃未提交草稿，不将旧身份的选择带回页面。

示例数据在原有样品 31、33、34、36、37、39、40、43、45、46、48、49 中提供入库阶段、已保存检测方案与站点/组号，保持样品总数不变。`inboundInfo` 是后端维护的可选模拟事实，不在样品编辑接口中开放修改。

方案筛选和主题设置抽屉统一通过 `src/services/common/offcanvas.ts` 管理互斥，等待前一个抽屉的关闭动画完成后再打开下一个；不会同时启用两个遮罩、焦点约束或滚动锁定。切换离开方案筛选时按关闭流程回填已选草稿，并中止未完成的初始化请求。Esc、动画期间关闭以及组件卸载使用同一清理流程，最后关闭时恢复页面焦点。

## 样品流转查询

`/samples/flow` 使用只读表格，没有行操作菜单。`POST /api/registration/samples/flow/query` 和 `/samples/flow/export` 接受 `code`、`status`、`plans`、`page`、`pageSize`、`sort`、`direction` 和可选 `ids`，按当前用户部门权限筛选。分页为 10/20/50 条，导出使用同一筛选条件，不受当前页限制。

流转状态包含样品已入库、样品已出库、样品已领取、检测已完成、样品待处置、样品已处置。后端将现有“样品入库完成／样品出库中”映射为“样品已入库”，“样品待领取”映射为“样品已出库”；作废及申请作废的样品不进入列表。入库、出库、处置人员及日期来自已保存的操作记录，撤销后的出库记录不显示为当前出库事实。领样、回库和客户取回签名预留在 `flowInfo`；未提供事实时返回空值，不从登记人或样品创建时间推断。

截图的“项目名称”对应 `testPlanName`（检测方案），表格提供 26 列及显示列选择。前四列依次为样品编号、委托编号、检测方案、样品/工程名称，委托编号和样品/工程名称默认隐藏；不再提供客户取回签名列。检测方案抽屉使用 `sampleScope: 'flow'`，方案节点附带 `flowSampleCount`，支持有样品／全部类别切换及本地整组选择，查询时由服务端校验范围。

四个日期范围默认过去一年，按流转阶段逐步启用：样品已入库启用入库时间；样品已出库启用入库、出库时间；样品已领取、检测已完成、样品待处置启用入库、出库、领样时间；样品已处置启用全部四项。“全部”禁用所有时间。查询和导出接收 `dates: { inbound?: { from, to }, outbound?: { from, to }, collection?: { from, to }, disposal?: { from, to } }`，前端仅提交已启用项，后端依据相同阶段规则忽略未启用项，对有效日期范围按 AND 筛选，包含起止当天；缺失该阶段日期的记录不匹配，不使用其他日期代替。切换状态保留各范围草稿，点击查询后将四组日期写入页面地址以支持刷新恢复；它们是否参与请求仍由当前流转状态决定。

## 检测任务分配

`/testing/assignment` 复用样品页面的表格、分页、显示列弹窗、日期控件和行菜单。查询条件按内容包含、数据状态、样品类型、结论状态、日期排列。样品编号、委托编号合并进内容字段选择；不再保留独立编号筛选。数据状态默认任务分配中，日期默认委托日期、过去一年；切换条件后点击查询生效，查询清空勾选并回到第一页。

`POST /api/registration/samples/assignment/query` 和 `/samples/assignment/export` 接收 `AssignmentQuery`：`searchField`、`contains`、`status`、`sampleType`、`conclusion`、`dateField`、`from`、`to`、`page`、`pageSize`、`sort`、`direction` 和可选 `ids`。服务端限定检测、复核、批准或管理员身份，并按人员部门范围筛选，仅返回任务分配中、任务分配完成且非作废/申请作废的样品。条件以 AND 组合，内容包含忽略大小写，日期包含起止当天。缺少日期不匹配指定的时间范围。分页为 10/20/50；导出与查询共用筛选，不受当前页限制。

20 列按截图顺序组织，末尾新增“附件”列，默认隐藏，可通过“显示”开启。列表返回样品自身的 attachmentCount，仅返回数量、不携带文件内容；有附件显示“有”，没有附件留空，导出采用同一规则。原项目名称列更名为检测方案，取样品检测方案名称；原工程名称列更名为项目名称，取样品委托信息的项目名称（commissionInfo.name），与样品单字典对应，查询选项同步更名。要求试验日期取 `details.requestedTestDate`，约定检测日期取已启用的 `details.appointmentDate`，两者分别处理。报告标题查询选项按样品单报告标题配置转换为可搜索名称。分配人、录入人、检测人1/2和结论来自可选 `assignmentInfo`，缺失时留空；已有 workflow 合格/不合格结论可用于筛选，不将未知结论归入其它。

依次提供分配、自动分配、撤销分配、打印任务单、任务处理记录、附件管理六个菜单。分配、自动分配及撤销分配规则见下文；打印任务单采用下述独立打印页。“附件管理”复用样品附件弹窗、接口及权限，上传、删除后只同步当前行版本与附件标记，不重新查询背景表格。演示数据复用现有样品 ID 增加独立的任务分配队列，不自动串联出入库操作。

### 任务处理记录

任务处理记录使用同一个大号弹窗切换列表、新增、只读详情和记录附件。顶部显示样品编号、样品/工程名称、检测方案；处理人按姓名或工号包含查询，处理日期默认过去一年，点击查询生效。固定显示序号、检测方案、样品/工程名称、处理人、处理时间、联系方式、沟通对象、处理内容、备注、附件，不提供显示列选择。每页默认 10 条，可选 20/50，按处理日期、实际提交时间倒序。附件列有附件显示“有”，否则留空。关闭保留任务分配列表的查询、分页及勾选。

以下接口前缀为 `/api/registration/samples/:id/task-processing-records`：

| 方法与路径 | 请求与响应 |
| --- | --- |
| POST `/query` | `{ handler?, from?, to?, page?, pageSize? }`；返回样品摘要、`canCreate`、`items/total/page/pageSize`。记录只含 `attachmentCount`，不含文件内容及审计事件 |
| POST 根路径 | `{ requestId, account, name, date, contactMethod, contactTarget, content, notes }`；新增并返回记录详情 |
| GET `/:recordId` | 返回只读详情、实际提交人和时间、独立版本、`canManageAttachments` |
| GET `/:recordId/attachments` | 返回记录详情及附件列表，下载前重新获取并校验权限 |
| POST `/:recordId/attachments` | `{ version, file: { name, type, size, dataUrl } }`；添加附件并返回更新后的附件上下文 |
| DELETE `/:recordId/attachments/:attachmentId` | `{ version }`；删除附件并返回更新后的附件上下文 |

处理人工号和姓名必填，默认当前用户且可修改，后台校验存在且匹配；处理时间为必填合法日期，默认当天。联系方式可选电话、微信、邮件、现场或自行填写，与沟通对象均选填且不超过 100 字；处理内容必填、备注选填，均不超过 500 字。后台读取样品的检测方案和名称保存快照，并独立记录实际登录提交人及提交时间，拒绝用客户端字段替换。记录不支持编辑、删除。

管理员和检测角色可在部门范围内为未作废、未申请作废且处于任务分配中/任务分配完成的样品新增记录、维护记录附件；有样品读取权限的其他用户只能查看和下载。每次请求重新校验权限、部门、样品状态及样品/记录/附件归属，状态变化后历史记录仍可读取。记录附件与样品、委托附件分开保存，单文件最多 20 MB，校验实际内容大小；附件写入校验记录版本并递增版本、追加操作审计，不更新样品版本、业务状态或分配信息。

记录保存在模拟后台会话的 `taskProcessingRecords` 集合中。相同样品、实际提交人和 `requestId` 的相同新增内容复用原记录；同请求标识提交不同内容返回版本冲突。新增成功回到第一页并查询，若不匹配当前筛选则提示已保存但不在筛选范围；失败保留草稿，未保存离开需确认。网络结果不确定时先刷新核对，不自动重试；新增手动重试保留请求标识避免重复，附件冲突要求刷新附件版本。附件变化只更新当前记录附件及列表标记，不刷新背景任务列表。

### 两行查询表单的更多筛选

检测任务分配默认显示查询内容、包含、数据状态、样品类型，将结论状态及日期放入“更多筛选”；样品流转查询默认显示样品编号和流转状态，将四组时间范围放入“更多筛选”。沿用已有链接按钮及上下箭头，按钮数量表示有值且可用的附加条件数量（默认的一年日期范围也计入）。收起不会清空或禁用条件，不触发查询；点击查询时仍提交有效条件。日期控件保持挂载以保留尚未提交的输入，校验失败时自动展开，便于修正。每次进入页面默认收起，URL 中保存的条件仍恢复。

### 分配对话框与提交

分配对话框复用出库弹窗及日期控件，顶部显示样品编号和名称，分配人工号、分配人姓名默认填写当前操作人的账号和姓名，均必填且可编辑，与出入库一致。数据录入人、检测人1必填，检测人2选填，初始均空白；分配日期必填、默认当天、可编辑。桌面端分配人工号与姓名并排，两名检测人并排，其余字段独占一行，手机端全部单列。

`POST /api/registration/samples/:id/assignment-action` 接收 `{ version, account, name, dataEntryPerson, tester1, tester2, date }`。服务端仅允许管理员/检测角色在自身数据范围内操作，校验记录版本、状态及人员。只有任务分配中且未作废/申请作废的样品可以分配。人员值优先按账号精确匹配，再按姓名精确匹配；姓名重名提示改填账号，不猜测人员。同一人员可同时录入和检测，但检测人1/2按人员ID判断不可重复。人员不存在、重复或日期无效返回字段级校验问题，不写入。

后台按 account 精确查找人员并校验 name 匹配，允许填写其他有效人员；不匹配在工号、姓名字段提示且不写入。分配人采用校验后的人员，实际提交人 recordedBy 始终取当前请求身份；权限和审计事件 actor 仍按实际提交人处理，忽略客户端伪造的 assignedBy、assignedById 和 recordedBy。成功后保留原 assignmentInfo 的结论等信息，保存 assignedBy/assignedById、dataEntryPerson/dataEntryPersonId、tester1/tester1Id、tester2/tester2Id、assignedDate、recordedAt 和 recordedBy；状态改为任务分配完成，版本递增并追加“分配”操作记录，返回更新后的样品。旧记录可缺少新增字段；不从其他日期补填历史分配日期。查询响应增加 version、canAssign，已完成和无执行权限的行禁用分配菜单。

前端等待提交成功才关闭并刷新当前查询、清空勾选；提交期间禁用按钮、输入与关闭。校验失败在字段旁显示提示并保留草稿，不显示诊断编号；服务失败可保留输入重试。版本冲突等失效条件禁用确认，提供刷新列表。身份切换、页面离开或查询更新后忽略旧请求对当前界面的反馈。

### 撤销分配

沿用出入库撤销的确认对话框：标题“撤销分配”，显示样品编号和样品/工程名称，提示确认及恢复“任务分配中”，提供取消、确认按钮，无新增填写字段。查询响应的 `canUndoAssign` 仅对有分配权限且处于任务分配完成的有效记录为 true，其他行禁用该菜单。

`POST /api/registration/samples/:id/assignment-action` 接收 `{ action: 'undo', version }`。未传 action 的原分配请求保持兼容，也可显式传 `assign`；自动分配使用下文的 `auto`，其余 action 拒绝。后台按当前请求身份校验管理员/检测角色、部门范围、工作空间锁定、记录版本以及未作废/申请作废的任务分配完成状态。成功恢复任务分配中，保留原 assignmentInfo（与出入库撤销保留办理信息一致），版本递增并以实际操作人追加“撤销分配”事件；再次分配时更新分配信息。失败不修改数据，并发或重复使用旧版本仅允许一次成功。前端等待成功后刷新当前查询并清空勾选，提交期间防止重复及关闭，版本冲突等失效条件要求刷新。

### 自动分配

点击行菜单“自动分配”先打开确认对话框，显示样品编号、名称和检测方案，提示确认按方案预设人员分配。打开或取消不发送分配请求；点击“确认”后关闭弹窗并提交，不发起人员预览请求。前端显示样品编号和“正在分配”，提交期间禁用任务操作。成功使用模板提示组件显示“样品 ×× 自动分配成功”，刷新当前查询并清空勾选。预设缺失、人员不存在或检测人重复使用业务提示，不显示诊断编号，并提供“手动分配”按钮，打开原有分配表单（当前操作人工号/姓名、当天日期，人员初始为空）。需要调整人员、分配人或日期时直接使用“分配”。

`POST /api/registration/samples/:id/assignment-action` 自动请求仅接收 `{ action: 'auto', version }`。后台在同一次写入中校验实际请求人的管理员/检测角色、部门范围、记录版本以及未作废/申请作废的任务分配中状态，读取当前检测方案人员预设，校验存在性和检测人重复，然后保存。数据录入人、检测人1必填，检测人2选填，数据录入人允许兼任检测人。分配人和实际提交人均为当前请求身份，分配日期取 serverDate()，记录实际提交时间，状态改为任务分配完成，版本递增并追加“自动分配”事件。失败不写入，并发或旧版本重复提交仅允许一次成功。

人员配置问题返回 VALIDATION，前端支持转手动。版本/状态变化要求刷新列表；网络及服务异常提示分配结果尚不能确认，要求刷新核对最新状态后操作，不自动重试，也不直接转手动。刷新、身份切换、页面离开或查询更新后忽略旧请求的反馈。后端已保存但列表刷新失败时分别呈现分配成功和查询错误，不将刷新失败当作分配失败。

旧请求如携带人员、分配人、日期、previewToken 或其他额外字段，返回 BAD_REQUEST 并提示刷新页面，不忽略用户旧页面的填写值执行自动分配。assignment-preview 接口、预览类型、凭据、会话缓存和预览错误码均已移除；旧预览请求返回 404。手动分配与撤销分配保持原协议。

当前模拟后台示例预设：general-1（常规检测方案）的数据录入人和检测人1均为 analyst（李检测），检测人2未配置。其他方案没有默认人员，不根据历史数据猜测。配置位于后端 autoAssignment 模块；人员配置入口另行设计，本次不提供批量自动分配或工作量推荐。

| 方法与路径 | 说明 |
| --- | --- |

查询状态失败只重试读取，不重复提交。提交结果不明时要求刷新打印资料核对；版本冲突同样要求刷新。身份切换或离开页面后忽略旧响应并释放 PDF 地址。当前队列与现有模拟后台一致，保存在服务器会话内；服务器重启或会话清除后不保留。演示队列沿用正常、慢速、失败、过期模拟场景，自动化测试可用 scenario 指定。正式模板与生产持久化队列另行实现。

## 检测数据录入列表

页面 `/testing/data-entry` 复用检测任务查询布局。本期提供列表、查询、显示列、检测方案筛选、分页及导出；数据录入、录入完成、撤销完成、查看数据、报告预览、取消任务保留禁用入口并标明“待实现”，不触发业务写入。大型多标签录入表单及其状态规则另行设计。

- `POST /api/registration/samples/data-entry/query`：返回分页列表及 `planSelection`。
- `POST /api/registration/samples/data-entry/export`：按同一查询条件或 `ids` 导出 CSV。
- 查询 `searchField`：`code`（样品编号）、`customer`（委托单位）、`contact`（委托人）、`engineeringName`（项目名称）、`dataEntryPerson`（数据录入人）、`reportTitle`（报告标题），配合 `contains` 包含查询。编号并入查询内容，不提供单独编号框；分项工程已按要求移除。
- `status`：空字符串为全部，另支持“检测数据录入中”“检测数据录入完成”。页面默认“检测数据录入中”；全部仅包含这两个阶段的有效样品，不含作废及申请作废。
- `dateField`：`commissionDate`、`requestedTestDate`、`testStartDate`、`testEndDate`；`from`/`to` 两端包含，缺失日期不匹配日期范围。页面默认委托日期及过去一年。
- `sampleType` 和 `conclusion` 选项与任务查询一致。`plans` 沿用现有方案选择结构，`test-plans/selection` 的 `sampleScope` 支持 `data-entry`，方案树返回 `dataEntrySampleCount`。
- `page` 默认 1，`pageSize` 默认 10、支持 20/50；排序支持 `code`、`commissionDate` 和 `asc`/`desc`。查询在分页前组合过滤；导出使用同一范围。

列按截图提供 20 项。检测方案来自 `details.testPlan`；项目名称查询使用样品关联委托项目名称（与任务查询一致）；指定主检人来自 `details.inspector`；分配人、分配日期来自 `assignmentInfo`；试验起止日期来自 `workflow.testStartDate/testEndDate`。试验人1/2预留读取后台 `dataEntryInfo.tester1/tester2` 的实际试验记录，缺失时留空，不使用分配的检测人代填。报告标题、结论状态沿用任务查询映射。附件数量来自样品附件，有附件显示“有”，无附件留空。

默认显示样品编号、报告编号、样品类型、样品/工程名称、检测参数、当前数据状态、要求试验日期；检测方案、指定主检人、附件等补充列默认隐藏，可由显示列面板开启。

读取/导出沿用检测任务权限（管理员、检测、复核、批准角色）及部门范围。行 `canReturn` 由后台按实际登录人的检测权限返回。退回复用 `POST /api/registration/samples/:id/task-return` 和“退回委托”弹窗；新增允许上述两个录入阶段，版本、权限、范围、作废限制及退回去向仍由后台校验。旧检测任务查询的状态选项保持不变。

附件管理复用样品附件弹窗和接口；录入完成后按既有规则仅可查看、下载。上传/删除成功只同步当前行版本及附件标记，不刷新列表或清空勾选。切换查询、离开页面或切换身份后不将旧请求结果应用到新列表。

报告预览建议后续在行菜单和数据录入表单提供同一预览入口，并基于已保存数据生成；本期不新增报告模板或生成服务。

- 附件草稿沿用 `/attachment-drafts/:id/*`，增加 `scope: equipment`。附件先上传到草稿，保存设备时解析引用并提交，失败保留草稿供重试。查看返回已保存附件；取消表单释放临时附件。

`EquipmentModal` 复用公共弹窗、日期、表格、工具栏、提示与上传组件。七个标签按旧页面字段组织；新增设备的管理报告列表为空，不编造关联报告。“保存并复制”成功后新建独立草稿，保留基本信息与项目，清空档案号、出厂号、四类历史记录和附件。模拟数据保存在当前后端会话，刷新页面可查询；不代表正式业务接口。

设备检测方案选择复用现有树形组件与方案目录：`POST /api/registration/quality/equipment/ledger/plans` 按分组或关键词分页查询；`POST /api/registration/quality/equipment/ledger/plan-selection` 在打开选择对话框时返回授权目录索引和已有选择。单项、分组和全部勾选（含半选和排除项）在本地即时计算，不逐次请求。两个接口按设备模块角色及当前部门授权，使用统一查询延时。确定后将方案代码、名称写入设备草稿；返回或关闭取消本次选择，不改变设备草稿。保存时以目录校验方案 ID 和访问范围并补全名称、代码。

## 客户管理：账号管理（模拟接口）

`/customers/accounts` 使用公共查询表单、表格、弹窗和未保存确认。列表提供客户账号、客户名称查询，显示客户账号、客户名称、备注；行菜单提供修改账号、查看账号、密码重置，无删除入口。新增/修改表单含账号信息、关联合同两页签，合同选择复用合同目录接口与公共表格。关联增删保存在草稿中，保存账号时统一提交，移除关联不会删除合同。

- `POST /api/registration/customers/accounts/query`：客户账号/名称模糊查询及分页。
- `POST /api/registration/customers/accounts/detail`：读取账号及关联合同。
- `POST /api/registration/customers/accounts/save`：客户名称必填，客户账号由服务端生成且不可修改；保存联系信息及合同 ID，并校验合同有效性和部门范围。沿用最新保存结果，不做版本确认。
- `POST /api/registration/customers/accounts/reset-password`：独立确认后生成随机临时密码，仅本次响应返回；服务端保存随机盐、scrypt 摘要、首次登录需修改标记及重置人/时间，查询详情不返回凭据。

有角色的演示身份可按部门范围查看；管理员、业务受理角色可维护及重置密码。账号数据保存在当前模拟后端会话，刷新保留。当前工程尚未提供客户门户登录，首次登录修改密码标记需要在正式认证后端接入时执行；本页不实现客户登录或密码投递。

账号管理列表统一接入公共 `TableToolbar`：支持导出查询结果（跨分页）和已选记录；显示列设置写入查询参数，刷新保留并支持恢复默认。`POST /api/registration/customers/accounts/export` 沿用查询条件、部门权限和可选 `ids`，输出客户账号、客户名称、备注三列 CSV；显示列设置不缩减导出字段，与其他基础资料页一致，不导出密码或凭据。
